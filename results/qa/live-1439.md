## 3. Bugs (steps, screenshots)

1. Most listed docs have no data on the deployed backend (about 98% of 847). Steps: Data, search a Swiss or opening_design doc, open it, ask anything. Result: preview blank or "Page preview unavailable", chat spends 14-29 s and $0.02-0.04 to say "I have no structured data". Shots: `swiss-01-data-details`, `btn-data-details`, `pdf-04-answer`.
2. Wrong answers on filter, compare, take-off questions (table above): 1.8 m doors returns 77, compare returns one floor, tiles m2 returns a count, windows-vs-doors returns windows only.
3. No-doc project questions search only 22 docs: "Which drawings have a door schedule" says none; kitchen list shows `upload-fixture-...` and omits AC20; "How do I read a door schedule" refuses while other generic questions answer.
4. Latency: 17-29 s for refusals and reader answers; PDF upload 84 s; one stream ended silently with "No answer yet." and left the composer text with no retry (`pdf-04-answer`).
5. IFC answers show 0 numbered boxes in 2D; numbers appear only in 3D, as overlapping label clusters, storey defaults to one floor (`ac20d-04-answer`, `phac20-05-3d`).
6. Number and unit errors on PDFs and uploads (Reception 741 m2 is the Lounge; door count 39 vs 38; upload "sinks and toilets" returns one sink).
7. Rendering: raw markdown table pipes (`pdf-06-answer`), raw `**` in citation quotes, internal ids like `room-004` in answers, up to 21 citation chips, "Where it is set out" boilerplate on one-liners.
8. Chat header (New/History/Share) overlaps the user bubble when the drawing split pane is open.
9. Test junk in Overview, Changes and History (`upload-fixture-...`, `...-generated-for-demo`, "Cross-device 1794...", duplicated titles, "Size unavailable", "Version count unavailable").
10. Infra: Aiven restart (14:17 EET) gave 302 to the Aiven status page and 502s for about 10 s; WebSocket `wss://...aiven.app/ws` returned 502/302 so live sync is broken on deploy; uploaded docs are not findable by doc_id in Data search; `/api/bench/latest` 404; 30 req/min limit surfaces as raw "rate limit exceeded" (`phcubi-03-answer`) with no countdown or retry.
11. Share gives no feedback on click for an empty chat (`btn-hdr-Share`).
12. Same question differs between API and UI (CubiCasa largest room "OH" vs "room-004").

## 4. Top 10 fixes, worst first for a judge

1. Bake or ingest the docs judges will actually open (Swiss, opening_design sheets, anything listed in Data), or hide docs without data. Today a random pick yields blank preview plus a paid refusal.
2. Fix the answers that are confidently wrong: width/size filters (9 not 77), comparisons (both floors), m2 take-offs (area, not count), windows-vs-doors.
3. Make the no-doc project search cover all baked docs (door-schedule and kitchen questions), and answer generic questions consistently.
4. Cut refusal and reader latency (17-29 s) and refuse fast with no model spend when no data exists; add a visible retry for "No answer yet."
5. Show numbered boxes in 2D for IFC answers (or auto-open 3D with all floors involved) so proof is visible at first glance.
6. Correct PDF and upload numerics (unit conversion SF to m2, door counts incl. 121.A/B, upload fixture counts).
7. Render markdown tables, strip `**` and internal ids, cap citation chips, drop boilerplate on short answers.
8. Fix the header overlap with the split pane and give Share/New visible feedback.
9. Clean test junk before the demo (`scripts/demo_reset.py` on deployed DB), fix size/version "unavailable" labels, publish a bench run so Accuracy is not empty.
10. Harden the deploy: keep-alive or restart-safe proxy, working WebSocket, friendlier 429 with retry countdown.
